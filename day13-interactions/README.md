# Day 13 — Interactions

- DATE: 13-11-2026
- NAME: Interactions
- ビューワ: https://shiwaku.github.io/30daymapchallenge-2026/day13-interactions/site/

## Description（公式）

> Interactions between things, or maybe the result would be an interactive map?

## Description（日本語訳）

物と物とのあいだのやり取り。あるいは、結果がインタラクティブな地図になるかも？

## 地図のテーマ

通勤は都心へ、私事は近所で（東京都市圏の OD 量図）

## 内容

第6回東京都市圏パーソントリップ調査（2018年＝平成30年）の基礎集計 表d-1「目的種類別代表交通手段別OD表」から、平日1日に計画基本ゾーン（615ゾーン）のあいだを動くトリップ数（OD 量）を、線（deck.gl の ArcLayer）で描く。線は出発地（青）から到着地（橙）へ色が変わり、太さはトリップ数に比例する（少ない線は薄い）。同じゾーンの中で終わるトリップは円で描く（面積が数に比例）。お題の2つの読み方に両方で答える。ゾーンどうしのやり取りを描き、ブラウザで選んで見られるようにした。

- 開くと都市圏全体。いまの条件で多い順に1,000本の流れを描く。URL に `?core` を付けると東京駅から約40kmの範囲に寄せる
- 目的（全目的／通勤／通学／私事／業務／帰宅）と代表交通手段（全手段／鉄道／バス／自動車／自転車／徒歩）を切り替えられる
- ゾーンをクリック（または名前で検索）すると、そこを出る流れと、そこへ来る流れに切り替わる。パネルに、そこを出発するトリップ、同じゾーンの中で終わる割合、ほかのゾーンから来るトリップ、行き先・来る元の上位5つを出す（名前をクリックするとそこへ移る）
- 線にマウスを乗せると、どこからどこへ何トリップか（目的別、または目的を選んでいれば手段別の内訳）を出す
- URL に `?z=0010`（計画基本ゾーンコード）を付けるとそのゾーンから開く。`&p=私事`、`&m=鉄道`、`&dir=out|in` も使える

主な数字（平日1日、トリップ）:

| 項目 | トリップ |
|---|---|
| 計画基本ゾーンどうしの OD の合計 | 70,329,179 |
| うち同じゾーンの中で終わる | 27,807,392（39.5%） |
| うちゾーンをまたぐ | 42,521,787（60.5%、79,359組） |
| ビューワに線として載せた組（全目的・全手段で500トリップ以上） | 30,806,874（17,966組、ゾーンをまたぐ分の72.4%） |

ゾーンをまたぐトリップの内訳: 目的は帰宅 18,111,182、通勤 10,973,808、私事 8,772,848、通学 2,210,360、業務 2,210,496、不明 243,093。代表交通手段は鉄道 22,844,449（53.7%）、自動車 11,131,386、自転車 3,474,714、徒歩 2,622,573、バス 1,344,875、その他（二輪車・その他・不明）1,103,790。

目的で比べると（平日1日、計画基本ゾーンどうし）:

| 目的 | ゾーンの中で終わる割合 | ゾーンをまたぐトリップのうち都心3区（千代田・中央・港）へ |
|---|---|---|
| 通勤 | 17.9% | 18.9% |
| 私事 | 52.9% | 7.8% |

例: 千代田区（東京駅付近、ゾーン0010）へほかのゾーンから来るトリップは 369,463。うち通勤 245,953、私事 68,248、業務 50,770。

## 言える範囲

- 2018年秋の平日1日の調査（抽出調査を拡大した値）。休日、コロナ禍以後の変化は表れない
- 単位はトリップ（ある目的で、ある地点から別の地点へ移動する1回の動き）で、人数ではない。1人が往復すれば2トリップ（行きと帰宅）
- 抽出調査なので、小さい組ほど誤差が大きい。そのため線は全目的・全手段で500トリップ以上の組だけにした（目的や手段で絞ると、1本あたりの値はもっと小さくなる）。パネルの数（出発・来る・ゾーン内）は、切る前の全件から数えた
- 代表交通手段は、1つのトリップで使った手段のうち主なもの。鉄道で通勤したトリップは、駅まで歩いても「鉄道」に入る
- 目的は d-1 の目的種類をまとめた。通勤 = 自宅－勤務、通学 = 自宅－通学、私事 = 自宅－私事＋私事、業務 = 自宅－業務＋勤務・業務、帰宅 = 帰宅。手段の二輪車・その他・不明は「その他」として全手段にだけ入る
- 圏域の外や、ゾーンが「不明」のトリップは入れていない（計画基本ゾーンどうしの行だけを使った）
- 線の端はゾーンの形のおおよその中心（いちばん大きい部分の重心。外れるときは内側の点）で、実際の出発地・到着地ではない。線は直線の弧で、通る道ではない
- ゾーンの名前は目安。市区町村名は小ゾーンの面積でいちばん多いものを使い、同じ市区町村に複数のゾーンがあるときは、ゾーン内で2018年の乗降客数が最も多い駅の名前を「○○駅付近」として添えた（駅がなければゾーンコード）
- 全体表示は多い順の1,000本だけ。隣り合うゾーンのあいだの短い流れが上位を占める

## 使用する技術

- Python（pandas で d-1 を読む、GeoPandas・Shapely でゾーンの形と線の端の点・名前を作る）
- Vite 8 ＋ MapLibre GL JS 6 ＋ deck.gl 9（`ArcLayer` を `MapboxOverlay` で MapLibre に重ねる。TypeScript）
- 目的・手段・ゾーンの絞り込みは、ブラウザの JavaScript で配列から引く
- 線の太さはトリップ数に比例（ピクセル単位、上限あり）。引いて見るときは細くする（ズーム10で1倍、最小0.3倍）。少ない線は薄くする
- スクリーンショットは playwright-core（Chrome）
- 公開版は `site/`（`npm run build` の出力）。GitHub Pages では /day13-interactions/site/。`web/` を `../web/` で読む

## 作り方

```sh
# data/pt/ に次を置く（Git 管理外）
#   d-1.zip   協議会の「データの提供」（https://www.tokyo-pt.jp/data/01_02）の第6回（H30）基礎集計から
#   H30_gis/  https://www.tokyo-pt.jp/static/hp/file/data/H30_gis.zip を展開
#   S12/      国土数値情報 S12-23 の UTF-8 版 S12-23_NumberOfPassengers.*
python -I -X utf8 scripts/build_pt.py data/pt web   # web/ に出力
npm install
npm run dev     # http://localhost:5173/
npm run build   # site/ に出力
node scripts/shot.mjs http://localhost:5173/   # output/ にスクリーンショット
```

`build_pt.py` は、d-1 の「計」の行と、市区町村などの合計行・「不明」ゾーンの行を除き、計画基本ゾーンどうしの行だけを使う。手段の列の合計が「計」と全行で一致することを確かめている。

はじめは2020年国勢調査の市区町村間の通勤・通学（全国）で作っていたが、目的と交通手段まで切り替えられる東京都市圏パーソントリップ調査に変えた。
