## Description（公式）

## Description（日本語訳）

## 地図のテーマ

公図を5分で地図に載せる

## 内容

法務省の登記所備付地図データ（地図XML）には、位置の分からない「任意座標系」の地区がある。筆（土地の区画）の形は正しいが、どこにあるか・どちらを向いているかが分からない。その1つ（広島県熊野町の `34307-2400-17.xml`）を、QGIS の中の AI アシスタント（Mapsuke）に頼んで公共座標（平面直角座標系 第III系）に位置合わせし、オルソ画像の上に表示するまでを録画した。

- 頼んでから地図ができるまで約5分（録画では 15:09:50〜15:15）。動画はそれを4倍速にした67秒
- 頼んだのは次の1文だけ。あとは AI がコードを書いて実行し、途中のエラーも自分で直した

  > 熊野町の地図XML（34307-2400-2026.zip の 34307-2400-17.xml）を moj-georef で位置合わせして。出力は data/align/day07b/34307-2400-17.gpkg にして（既存の結果は上書きしないで）。終わったら、オルソ画像（2016年度 QE193）と CS立体図を背景にして、aligned を reliable で色分けして表示して。

- 青は「信頼できる」位置合わせ、赤は「要確認」

### 位置合わせのしかた

位置合わせは自作の [moj-chizu-xml-georeference](https://github.com/shiwaku/moj-chizu-xml-georeference)（手法は [docs/method.md](https://github.com/shiwaku/moj-chizu-xml-georeference/blob/master/docs/method.md)）で行う。人がジオリファレンスするときと同じく「住所でだいたいの場所を探す → 道路や地形の線に重ねて細かく合わせる」の2段階。

1. **エリアに分ける**: 15m 以内の筆をまとめて1つのエリアにする（XML の中でも図郭ごとに別の局所座標のことがある）
2. **大まかに置く**: 筆の地番（`215-4` なら `215`）を国土地理院の住所検索で引き、番地の位置と筆の重心を対応点にして、移動と回転を最小二乗で求める。精度は数十m
3. **細かく合わせる**: 1.の周り（±80m・±8°）で、筆界線が参照線にいちばんよく乗る位置・回転・縮尺を探す
   - 参照線は、基盤地図情報の道路縁・水涯線と、0.5m DEM の曲率の大きい所（法面・段差）
   - 公共座標の筆と重なる、筆の中に段差が多い、筆界が建物を横切る、の3つは罰則にする
   - 回転・縮尺の組ごとに、すべての平行移動の評価を FFT でまとめて計算し、上位の候補を Nelder-Mead 法で詰める
4. **信頼度**: 1位と2位の候補の評価の差（gap）が 1.0 以上なら「信頼できる」とする。似た街区が並んでいて区別できないと gap が小さくなる
5. 信頼できないエリアは、信頼できたエリアの回転の中央値を中心に、範囲を広げて（±250m・±10°）探し直す

変換は相似変換（移動・回転・縮尺）だけで、公図の中の歪みは直さない。

## 言える範囲

- 「10分」は、頼んでから地図ができるまでの時間（約5分）。データのダウンロード、DEM・オルソ画像・CS立体図の用意、位置合わせのツールとAIへの手順書（スキル）は、前もって作ってあった
- 「信頼できる」は gap の基準によるもので、正しいことの保証ではない。公共座標の図郭をわざと崩して戻す評価では、gap 0.5 以上に誤りはなかった（ツールのリポジトリの評価）。任意座標系の地区での精度の根拠は、オルソ画像との目視（1m 前後）だけ
- 結果は XML を1つだけで実行したもの。熊野町全体で実行すると、2周目の回転の基準が変わるので、少し変わることがある
- 実験段階の結果で、登記や測量の判断には使えない。登記所備付地図データは地図証明書の代わりにならない
- 基盤地図情報ベクトルタイル（experimental_fgd）は2014年時点。それより後に造成・建て替えされた所は、線がないかずれている

## 使用する技術

- QGIS 4.0 と、その中の AI アシスタント Mapsuke（Claude Opus 5.5）
- [moj-chizu-xml-georeference](https://github.com/shiwaku/moj-chizu-xml-georeference)（Python、NumPy・SciPy の FFT と Nelder-Mead）を、QGIS 同梱の Python から呼ぶ
- 録画は ffmpeg の画面録画（gdigrab）。AI の画面の外の作業（ターミナル）が映った約43秒は切り、4倍速にして出典の帯を足した

## 生成AIの使用

位置合わせの実行と QGIS の操作は、QGIS の中の AI アシスタント（Claude）が行った。位置合わせのツールのコード、録画と動画の編集、README の下書きにも Claude（Anthropic、Claude Code）を使った。
